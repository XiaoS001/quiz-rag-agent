## 4. 文档间相似度分布

- 685 条文档向量两两余弦相似度均值：**0.502**，标准差：**0.079**。
- 已实测的另一组结果是 top1 到 top5 分数极差仅 **0.022 到 0.154**；本次 12 题重新运行得到的结果见下一条，两组都说明分数间距很窄。
- 本次 12 个问题的向量 top1 与 top5 分差范围为 **0.015 到 0.212**，首尾分数非常接近时，排序容易被短文本细节扰动。
- 原因：题库几乎全是同一知识域下的短文本，而且文档文本拼入了“答案 + 解析”；答案和解析又大量复用同一批术语，导致文档向量整体聚拢。
- 浅层影响：相似分数看起来普遍不低，但分数高低不等于题目真的回答了问题；必须结合首条题干和人工判断，不能只看余弦分数。

- `B+树`、`MySQL`、`死锁`、`红黑树`在当前题库中对应知识为 0 道。
- 问“什么是死锁”时，模型仍返回门禁卡鉴别题；问“MySQL 索引为什么用 B+ 树”时，返回的是 Python 列表索引、构造参数 index、字典索引，只是共享了“索引”这个词，并不是数据库索引知识。
- 结论：向量检索在没有对应知识时不会天然说“不知道”，而是给出向量空间最近的题目。这是它相对 BM25 的真实风险，必须在上层 Agent 或回答层加“材料是否真正支持问题”的校验。

### 结论

- BM25 平均耗时 **1.565 ms**，向量检索平均耗时 **3.823 ms**，约为 BM25 的 **2.44 倍**。
- 关键词类平均重合 **3.00/5**，同义改写类 **2.00/5**，概念模糊类 **3.00/5**。
- 向量检索因为稠密分数一定返回 top-5，所以“有返回”不能当作“更准”；本题库规模下，低重合更多是在说明两套排序信号差异很大。

### 具体判断

- 向量检索有明确胜出的例子：`Spring 声明式事务是怎么工作的` 中，BM25 首条是 id 57“下列选项中，关于Spring框架优点的说法不正确的是（ ）。”，向量首条是 id 17“Spring提供了____注解来实现声明式事务管理。”，后者直接命中声明式事务注解。
- BM25 也有明显更好的例子：`请求进入控制器之前怎样统一拦截处理` 中，BM25 首条是 id 33“Spring MVC的____使得开发者能够在请求进入处理器之前、处理器处理完请求后以及渲染视图之后执行...”，直接描述拦截器；向量首条是 id 154“拦截器的preHandler()方法会在请求处理之后被调用。（ ）”，虽然同属拦截器，但题干在描述错误说法。
- 同义改写并不保证向量一定成功：`怎样让重复的数据库查询复用已有结果` 中，BM25 首条是 id 236“48、Python中可变集合和不可变集合的共同特点是____和____”，向量首条是 id 536“52、函数可以提高代码的复用性。”，两者都没有找到 MyBatis 缓存题。
- 关键词题里 BM25 更贴近原句，例如 Spring 依赖注入题两版首条同为 id 190；MyBatis 动态 SQL 和 MyBatis 缓存题则出现相近主题但不同排序。

### 实话结论

在这份 685 题、短文本、主题混杂的中文题库上，这次实测没有证明`bge-small-zh-v1.5` 向量检索全面优于 BM25。BM25 在多数问题上的首条结果至少不差，而且平均耗时低得多；向量检索在“Spring 声明式事务”这样的语义问题上展现了价值，但也会被短文本和相似术语干扰。更可信的工程结论是：BM25 适合作为当前小语料的主检索，向量检索作为补充召回，再叠加人工标注、重排或混合评分，而不是单独宣布某一版胜出。

注：本次没有人工 ground truth 标注，判断以首条题干相关性、top-5 重合度和明确列出的代表案例为准，不是 nDCG/MRR 级别的离线评测。
